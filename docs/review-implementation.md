# Learn / Review 구현 및 배포 안내

## 구현 범위

- Learn: 좁은 화면에서 콘텐츠가 부모 너비를 넘지 않도록 보완하고, 빠른 연습 카드는 사용 가능한 너비에 따라 열 수를 결정한다.
- Progress: 최근 학습 번들 카드의 진행 정보와 이어서 학습 동작을 현재 번들 학습 기준에 맞춘다.
- Review: 예정일과 오답 여부를 기준으로 추천하며 기본 10개를 먼저 선택한 후 섞는다. 모드별로 실행 가능한 항목만 사용한다.
- 세션 종료 시 첫 응답 기준 결과, 저장 상태, 다음 복습을 안내한다. 오답 다시 보기는 추가 점수를 저장하지 않는다. 문장 플래시카드는 읽기 전용이다.
- 저장 실패 시 같은 시도 ID로 재시도한다. 새 복습 API는 권한과 항목 관계를 검증하고, 학습 기록·통계·일별 집계·시도 기록을 하나의 트랜잭션으로 저장한다.
- 세션 시작/종료 집계는 중복 호출에 안전하며 문제 내용이나 사용자 답안 원문을 수집하지 않는다.
- 학습 현황에서 시작한 복습은 종료 후 원래 학습 현황으로 돌아갈 수 있다.

기존 숙련도와 복습 간격 정책은 유지한다. 이번 트랜잭션 적용 범위는 새 복습 결과 API이며 기존의 모든 학습 저장 경로를 전환한 것은 아니다.

## 배포 순서

1. 대상 Supabase 프로젝트에서 기존 선행 마이그레이션 적용 상태를 확인한다.
2. `supabase/migrations/20261024090000_add_atomic_review_attempts.sql`을 프로젝트의 정상적인 마이그레이션 배포 절차로 적용한다.
3. 새 애플리케이션 코드를 배포한다. 새 복습 API가 위 마이그레이션의 테이블과 RPC를 사용하므로 DB를 먼저 적용해야 한다.
4. 테스트 계정으로 복습 응답 저장, 종료 후 목록 갱신, 학습 현황 복귀를 확인한다.

이 작업에서는 원격 DB에 마이그레이션을 적용하거나 서비스를 배포하지 않았다. 앱을 이전 버전으로 되돌릴 경우 추가 테이블은 유지할 수 있다. 이미 저장된 시도 기록을 임의로 삭제하지 않는다.

## 검증

```sh
npm test
npm run test:review
npx tsc --noEmit
npm run build
npx playwright install --with-deps chromium
npm run test:review:browser
```

- 로직 테스트: 복습 우선순위, 개수 제한, 모드별 유효성, 요청 검증 및 기존 학습 회귀 검사.
- 저장 테스트: PGlite PostgreSQL 엔진에서 실제 마이그레이션을 적용하여 중복 저장, 충돌, 전체 롤백, 스냅샷 변경, 단어/문장 관련 집계, 세션 집계의 멱등성을 확인한다.
- 브라우저 테스트: 실제 복습 컴포넌트를 Chromium에서 실행한다. 320/375/768/1024/1280px, 다크 모드 가로 넘침, 자동 시작, 저장 재시도, 유형 전환, 원래 학습 현황 복귀, 오답 재연습과 읽기 전용 모드의 중복 저장 방지를 확인한다.

브라우저 검사는 인증·네트워크 응답을 fixture로 대체한다. 운영 인증 및 실제 Supabase 연결까지 확인하는 배포 후 검증을 대체하지 않는다. Learn/Progress 전체 페이지의 실서비스 데이터 조합도 배포 후 확인한다.
